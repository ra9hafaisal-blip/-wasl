# نشر وَصْل مجانًا للتجربة عبر Render

المستودع موجود على GitHub، لكن `http://127.0.0.1:8000/` عنوان محلي لا يفتحه إلا جهازك. أُضيف ملف `render.yaml` و`Dockerfile` حتى يجهز المشروع للنشر على Render.

## خطوات النشر

1. افتح [Render](https://render.com/) وسجّل الدخول بحساب GitHub.
2. اختر **New → Blueprint**، ثم اسمح لـ Render بالوصول إلى المستودع `ra9hafaisal-blip/-wasl` واختر الفرع `main`.
3. راجع الموارد التي يعرضها ملف `render.yaml`، ثم أنشئها. الإعداد يختار خطة **Free** لخدمة الويب وقاعدة PostgreSQL.
4. انتظر اكتمال البناء والنشر. افتح خدمة `wasl-app` وخذ الرابط الذي ينتهي بـ `onrender.com`.

الإعداد يولّد `APP_KEY` ويربط قاعدة البيانات تلقائيًا، ويشغّل ترحيلات Laravel عند بدء التطبيق. لا ترفع `.env` أو قاعدة SQLite المحلية إلى GitHub.

## حدود الخطة المجانية

- خدمة الويب تدخل في وضع السكون بعد 15 دقيقة دون زيارات، وقد يستغرق فتحها التالي نحو دقيقة.
- قاعدة PostgreSQL المجانية تنتهي بعد 30 يومًا. ترقّ إلى قاعدة مدفوعة قبل ذلك إذا أردت الاحتفاظ بالبيانات.
- نظام الملفات في خدمة الويب مؤقت؛ لذلك يستخدم الإعداد PostgreSQL بدل SQLite.
- الخطة المجانية مناسبة لعرض المشروع أو تجربته، وليست استضافة دائمة مضمونة. [تفاصيل Render الرسمية](https://render.com/docs/free)

إذا لم تظهر لك **Blueprint** أو طلب Render إعدادات مختلفة، أرسل لقطة للشاشة وسأساعدك خطوة بخطوة. لا تشارك كلمة المرور أو أسرار قاعدة البيانات.
